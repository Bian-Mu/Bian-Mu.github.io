

### 1. 进程与线程 (核心中的核心)

*   **区别**
    进程（Process）和线程（Thread）是操作系统中并发执行的两个基本概念，它们的主要区别在于对资源的所有权。
    *   **资源分配单位 vs. CPU 调度单位**：进程是操作系统进行资源分配和拥有的最小单位。它拥有独立的内存地址空间、文件句柄、设备等。线程是 CPU 调度的最小单位，它本身不拥有资源，而是共享其所属进程的资源。
    *   **内存共享**：进程之间的内存空间是相互隔离的，一个进程崩溃不会直接影响其他进程。进程间通信（IPC）需要通过特定的机制。同一进程内的所有线程共享该进程的内存空间（如代码段、数据段、堆），但每个线程拥有自己独立的栈（用于存储局部变量和函数调用信息）和程序计数器。
    *   **切换开销**：由于进程拥有独立的资源，其上下文切换（Context Switch）开销较大，需要切换页表、内核栈等。线程切换则轻量得多，因为它发生在同一进程地址空间内，只需切换少量寄存器和栈指针，开销远小于进程切换。

*   **状态流转**
    一个进程或线程在其生命周期中会经历不同的状态，主要包括以下三种基本状态及其转换：
    *   **就绪态 (Ready)**：进程已具备运行所需的所有条件，只等待 CPU 分配执行时间。
    *   **运行态 (Running)**：进程正在占用 CPU 并执行其代码。
    *   **阻塞态 (Blocked/Waiting)**：进程因等待某个事件（如 I/O 操作完成、等待锁）而暂时无法继续执行，此时它不会占用 CPU 时间。

    **状态转换图**：
    1.  **就绪 -> 运行**：当操作系统的调度器选择一个就绪态的进程为其分配 CPU 时，该进程状态变为运行态。
    2.  **运行 -> 就绪**：当运行中的进程时间片用完，或者被更高优先级的进程抢占时，它会回到就绪态。
    3.  **运行 -> 阻塞**：当运行中的进程需要等待某个外部事件时（例如，发起一个读磁盘的操作），它会主动放弃 CPU，进入阻塞态。
    4.  **阻塞 -> 就绪**：当进程等待的事件发生后（例如，磁盘数据已读入内存），操作系统会将其唤醒，使其进入就绪态，等待下一次被调度。

*   **通信方式 (IPC)**
    *   **进程间通信 (Inter-Process Communication, IPC)**：
        *   **管道 (Pipe)**：半双工的通信方式，数据只能单向流动，常用于父子进程或兄弟进程之间。
        *   **消息队列 (Message Queue)**：一个存储在内核中的消息链表，克服了管道只能单向通信且容量有限的缺点。
        *   **共享内存 (Shared Memory)**：将一块物理内存映射到多个进程的地址空间中，允许它们直接访问。这是**最快**的 IPC 方式，因为它避免了数据在内核态和用户态之间的拷贝。
        *   **信号量 (Semaphore)**：一个计数器，主要用于控制多个进程对共享资源的访问，常作为一种锁机制，实现进程间的同步与互斥。
        *   **套接字 (Socket)**：更通用的 IPC 机制，可用于不同主机之间的进程通信。

    *   **线程间通信**：
        由于线程共享内存，它们的通信方式更多是关于**同步**和**互斥**。
        *   **互斥锁 (Mutex)**：确保在任何时刻只有一个线程可以访问被保护的代码段或数据。
        *   **读写锁 (Read-Write Lock)**：允许多个线程同时进行读操作，但只允许一个线程进行写操作，适用于“读多写少”的场景。
        *   **条件变量 (Condition Variable)**：与互斥锁配合使用，允许线程在某个条件不满足时挂起等待，直到其他线程改变了该条件并通知它。
        *   **信号量 (Semaphore)**：也可用于线程同步，控制同时访问特定资源的线程数量。

*   **协程 (Coroutine)**
    协程是一种比线程更轻量的并发实体，有时被称为“用户态线程”。
    *   **优势**：协程的调度完全由用户程序（或语言运行时）控制，不涉及操作系统内核。其创建和切换的开销极小，因为它不需要陷入内核，只是简单的函数调用和上下文保存。这使得在单个线程内可以轻松创建成千上万个协程来处理高并发任务。
    *   **Go 语言的 Goroutine**：Goroutine 是 Go 语言实现协程的机制。Go 运行时拥有一个强大的调度器，可以将多个 Goroutine 智能地映射到少数几个内核线程（M:N 模型）上执行，实现了用户态的轻量级并发与内核态的多核并行处理能力的结合。

### 2. 锁与并发控制

*   **死锁 (Deadlock)**
    死锁是指两个或多个进程（或线程）在执行过程中，因争夺资源而造成的一种互相等待的僵局。
    *   **产生的 4 个必要条件**：
        1.  **互斥 (Mutual Exclusion)**：资源在同一时间只能被一个进程占用。
        2.  **请求与保持 (Hold and Wait)**：一个进程在请求新资源而被阻塞时，对自己已获得的资源保持不放。
        3.  **不剥夺 (No Preemption)**：进程已获得的资源在未使用完之前，不能被强行剥夺。
        4.  **循环等待 (Circular Wait)**：存在一个进程资源的循环等待链，每个进程都在等待下一个进程所持有的资源。
    *   **如何避免/预防**：
        *   **破坏请求与保持条件**：要求进程一次性申请所有需要的资源。
        *   **破坏不剥夺条件**：允许操作系统在进程请求新资源得不到满足时，剥夺其已持有的资源。
        *   **破坏循环等待条件**：对所有资源类型进行线性排序，要求每个进程按顺序申请资源。

*   **锁的分类**
    *   **乐观锁 vs. 悲观锁**
        *   **悲观锁**：总是假设最坏的情况，认为数据在被访问时总会发生冲突，所以在数据处理前就加锁。数据库中的行锁、表锁都是悲观锁。
        *   **乐观锁**：假设数据一般情况下不会造成冲突，所以在数据提交更新的时候才去检查。 **CAS (Compare-And-Swap)** 是其典型实现。
        *   **CAS 原理**：一个原子的操作，包含三个操作数——内存位置 V、预期原值 A 和新值 B。当且仅当 V 的值等于 A 时，才将 V 的值更新为 B，否则不做任何操作。
        *   **ABA 问题**：CAS 的一个经典问题。如果一个值从 A 变为 B，又变回 A，CAS 检查时会认为它没有被修改过，但实际上已经发生了变化。解决方案通常是引入版本号，将 A->B->A 的过程变为 1A->2B->3A。

    *   **自旋锁 vs. 互斥锁**
        *   **自旋锁 (Spinlock)**：当一个线程尝试获取锁但发现锁已被占用时，该线程会进入一个忙等待的循环（自旋），不断地检查锁是否被释放。适用于锁占用时间非常短的场景。
        *   **互斥锁 (Mutex)**：当线程获取锁失败时，它会被挂起（进入阻塞态），让出 CPU。适用于锁占用时间较长的场景，可以避免 CPU 空转。

    *   **可重入锁 (Reentrant Lock)**
        也称为递归锁，允许同一个线程多次获取同一个锁而不会造成死锁。例如，一个函数获取了锁，然后它调用了另一个也需要该锁的函数，如果锁是可重入的，那么这次调用就能成功。

### 3. 内存管理

*   **虚拟内存 (Virtual Memory)**
    虚拟内存是操作系统提供的一种内存管理技术，它为每个进程提供了一个独立的、连续的虚拟地址空间。
    *   **为什么需要**：
        1.  **扩展地址空间**：通过将部分内存暂存到磁盘上，使得程序可以拥有远大于物理内存的地址空间。
        2.  **内存保护与隔离**：每个进程的地址空间是独立的，可以防止一个进程的错误操作影响到其他进程或操作系统本身。
        3.  **简化内存管理**：进程看到的都是连续的地址空间，无需关心物理内存的碎片化问题。

*   **分页与分段**
    *   **分页 (Paging)**：将虚拟地址空间和物理地址空间都划分为大小固定的块，分别称为**页 (Page)** 和**页框 (Page Frame)**。操作系统通过**页表**来维护页和页框的映射关系。分页是纯粹从计算机角度出发，为了管理方便。
    *   **分段 (Segmentation)**：根据程序的逻辑结构（如代码段、数据段、堆栈段）来划分内存。每个段的大小可以不同。分段是从用户和程序员的角度出发，便于逻辑管理。
    *   **区别**：页的大小是固定的，而段的大小是可变的。分页的地址空间是一维的，而分段是二维的（段号+段内偏移）。

*   **页面置换算法**
    当发生缺页中断且没有空闲物理页框时，操作系统需要选择一个页面将其换出到磁盘。
    *   **LRU (Least Recently Used)**：最近最少使用。替换掉最长时间未被访问的页面。
    *   **FIFO (First-In, First-Out)**：先进先出。替换掉最早进入内存的页面。

*   **缺页中断 (Page Fault)**
    当程序试图访问一个在页表中但当前不在物理内存中的页面时，会触发一个缺页中断。处理流程如下：
    1.  CPU 捕获到中断，程序执行暂停，操作系统介入。
    2.  操作系统检查该内存访问是否合法。
    3.  在磁盘上找到该页面对应的数据。
    4.  找到一个空闲的物理页框，如果找不到，则通过页面置换算法换出一个页面。
    5.  将所需页面从磁盘加载到物理页框中。
    6.  更新页表，标记该页面已在内存中。
    7.  返回到原程序中断处，重新执行该指令。

*   **堆与栈**
    *   **栈 (Stack)**：由编译器自动分配和释放，用于存放函数的参数值、局部变量等。栈空间较小，向低地址方向生长。
    *   **堆 (Heap)**：由程序员手动分配（如 `malloc`）和释放（`free`）。空间较大，向高地址方向生长，容易产生内存碎片。

### 4. I/O 模型

*   **五种模型**
    1.  **阻塞 I/O (Blocking I/O)**：发起 I/O 请求后，应用程序一直阻塞，直到数据准备好并从内核拷贝到用户空间才返回。
    2.  **非阻塞 I/O (Non-blocking I/O)**：发起 I/O 请求后立即返回，如果数据没准备好会返回一个错误。应用程序需要不断轮询内核，看数据是否就绪。
    3.  **I/O 复用 (I/O Multiplexing)**：允许单个进程监视多个文件描述符（Socket），一旦其中任何一个就绪，就通知应用程序进行读写。`select`, `poll`, `epoll` 是其三种主要实现。
    4.  **信号驱动 I/O (Signal-driven I/O)**：应用程序发起请求后立即返回，当数据准备好时，内核会发送一个信号通知应用程序。
    5.  **异步 I/O (Asynchronous I/O)**：应用程序发起 I/O 请求后立即返回，内核会在整个操作（包括数据从内核拷贝到用户空间）完成后，才通知应用程序。

*   **I/O 多路复用：select, poll, epoll 的区别**

| 特性           | select                                             | poll                 | epoll                                        |
| :------------- | :------------------------------------------------- | :------------------- | :------------------------------------------- |
| **底层实现**   | 位图                                               | 链表                 | 红黑树 + 双向链表                            |
| **描述符限制** | 有限制（通常是 1024）                              | 无限制（受限于内存） | 无限制（受限于内存）                         |
| **内存拷贝**   | 每次调用都需要将整个描述符集合从用户态拷贝到内核态 | 同 select            | 只需拷贝一次，后续通过 `epoll_ctl` 添加/修改 |
| **效率**       | 随着描述符数量增加，效率线性下降                   | 同 select            | 效率不随描述符数量改变，只与活跃的描述符有关 |
| **触发方式**   | 水平触发 (LT)                                      | 水平触发 (LT)        | 支持水平触发 (LT) 和边缘触发 (ET)            |
``
-  **epoll 原理**：
	内部使用一棵**红黑树**来存储所有被监听的文件描述符，并用一个**双向链表**来维护已就绪的描述符。当调用 `epoll_wait` 时，它只需检查这个就绪链表是否为空即可，从而避免了对所有描述符的轮询。
    - **水平触发 (LT)**：只要文件描述符处于可读/写状态，`epoll_wait` 就会一直通知。
    - **边缘触发 (ET)**：只有当文件描述符的状态发生变化（例如，从不可读变为可读）时，`epoll_wait` 才会通知一次。ET 模式效率更高，但要求程序必须一次性将缓冲区数据处理完毕。

*   **零拷贝 (Zero Copy)**
    零拷贝技术旨在减少甚至消除数据在内核缓冲区和用户应用程序缓冲区之间的冗余拷贝，从而提高 I/O 性能。
    *   **`sendfile`**：允许数据直接在两个文件描述符之间传输（通常是文件到 Socket），数据完全在内核态进行传递，避免了用户态的拷贝。
    *   **`mmap` (内存映射)**：将文件的内容直接映射到用户进程的地址空间中，应用程序可以直接像操作内存一样操作文件数据，读写操作由操作系统的缺页中断来完成，避免了 `read`/`write` 系统调用带来的拷贝。

### 5. 用户态与内核态

*   **内核态（Kernel Mode）**：也称为特权态（Privileged Mode）。在此模式下，CPU可以执行指令集架构中的**任何指令**，并访问系统中的**任何内存和设备**。操作系统的内核代码运行在内核态，它需要这种无限制的权限来管理硬件资源（如CPU、内存、磁盘）和调度进程。

*   **用户态（User Mode）**：也称为普通模式（Normal Mode）。在此模式下，CPU的权限受到限制。应用程序的代码只能执行一部分安全的指令，并且只能访问其被操作系统分配的私有内存空间。如果用户程序试图执行特权指令（如I/O操作、修改页表），CPU会硬件级别上阻止它，并触发一个异常。

这种区分确保了：
1.  **系统安全**：普通应用程序无法直接操作硬件，防止了恶意或有缺陷的程序破坏整个系统。
2.  **系统稳定**：内核作为管理者，可以统一、安全地为所有程序提供服务，避免了资源访问的冲突。
3.  **多任务处理**：内核可以强制剥夺某个失控应用的CPU使用权，保证其他应用能够正常运行。

#### **转换方式：从用户态到内核态**

##### 1. 系统调用 (System Call)

这是最主要、最常见的转换方式。当应用程序需要执行一项只有内核才能完成的操作时，它不能直接调用内核函数，而是通过**系统调用**这个特殊接口来请求服务。

**转换流程如下：**
1.  **应用程序执行 `int 0x80` 或 `syscall` 指令**：应用程序在其代码中调用一个库函数（如C语言的`printf`），这个库函数内部会封装一个特定的**软件中断**指令（在x86架构下是`int 0x80`）或更新的`syscall`指令。这个指令会告诉CPU：“我需要切换到内核态”。
2.  **CPU 中断/异常机制介入**：CPU在执行该指令后，会立即暂停当前的用户程序。
3.  **保存现场（上下文切换）**：CPU会将当前用户态的寄存器状态（如程序计数器PC、栈指针SP等）保存到内存或内核栈中。这个过程被称为“保存现场”，以便将来能准确地返回到中断前的位置。
4.  **加载内核上下文并跳转**：CPU根据中断向量表（Interrupt Vector Table）或特定寄存器，找到操作系统预设的**系统调用处理程序**的地址，然后将PC指针指向该地址，并将CPU模式切换到**内核态**。
5.  **内核执行服务**：进入内核态后，操作系统开始执行对应的内核代码（例如，执行文件读取操作）。
6.  **完成转换**：此时，CPU已经在内核态运行，完成了从用户态到内核态的转换。

##### 2. 异常 (Exception)

当CPU在执行用户态程序时，如果发生了无法处理的错误或特殊情况，也会触发从用户态到内核态的转换。

**常见的异常包括：**
*   **缺页中断（Page Fault）**：程序试图访问一个在虚拟内存中但尚未加载到物理内存的页面。
*   **除零错误**：程序执行了除以零的算术运算。
*   **非法指令**：程序试图执行一个CPU无法识别的指令或一个在用户态下不允许执行的特权指令。

**转换流程与系统调用非常相似**：CPU检测到异常 -> 保存用户态现场 -> 根据异常类型查找并跳转到内核预设的异常处理程序 -> CPU切换到内核态。

##### 3. 中断 (Interrupt)

中断主要指来自硬件设备的信号，通知CPU有某个事件需要处理。这种中断是**异步**的，因为它可能在任何时刻发生，与CPU当前执行的指令无关。

**常见的中断包括：**
*   **I/O 中断**：例如，磁盘完成了数据读取，网卡接收到了新的数据包。
*   **时钟中断**：操作系统设置的定时器到期，用于触发进程调度。

**转换流程**：硬件设备发送中断信号给CPU -> CPU暂停当前执行的用户程序 -> 保存用户态现场 -> 查找并跳转到内核的中断服务程序 -> CPU切换到内核态。

---

#### **转换方式：从内核态返回用户态**

当内核完成了为用户程序请求的服务（或处理完了异常/中断）后，就需要将控制权交还给用户程序。

1.  **内核准备返回**：内核代码执行完毕，准备返回。
2.  **恢复现场**：操作系统执行一条**特权指令**（如`iret`或`sysret`），这条指令会：
    *   从内核栈中弹出之前保存的用户态寄存器信息（PC、SP等），将其恢复到CPU的寄存器中。
    *   将CPU的模式从**内核态切换回用户态**。
3.  **继续执行用户代码**：CPU的控制权回到了应用程序，从之前被中断的那条指令的下一条开始继续执行。


### 6. Linux 常用命令

*   **系统监控**：
    *   `top`: 实时显示系统中各个进程的资源占用状况，如 CPU、内存使用率。
    *   `ps`: 显示当前进程的状态。`ps aux` 或 `ps -ef` 是常用组合。
    *   `netstat`: 显示网络状态信息，如网络连接、路由表、接口统计等。
    *   `lsof`: 列出当前系统打开的文件（List Open Files）。

*   **文本处理（三剑客）**：
    *   `grep`: 在文本中查找匹配的行。
    *   `awk`: 一种强大的文本分析工具，可以按列处理文本。
    *   `sed`: 流编辑器，用于对文本进行替换、删除、新增等操作。

*   **权限管理**：
    *   `chmod`: 修改文件或目录的访问权限。
    *   `chown`: 修改文件或目录的所有者和所属组。

*   **查看系统负载 (Load Average)**
    可以通过 `top` 或 `uptime` 命令查看。输出的三个数字分别代表过去 1 分钟、5 分钟和 15 分钟的平均负载。
    *   **含义**：Load Average 表示在特定时间间隔内，系统中**处于可运行状态（正在运行或等待运行）和不可中断状态（通常是等待 I/O）**的平均进程数。在单核 CPU 系统中，如果负载为 1.0，表示 CPU 正好满负荷。如果超过 1.0，则表示系统处于超载状态，有进程在排队等待 CPU。
